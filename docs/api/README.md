# API Documentation

The API is documented **from code**: FastAPI generates an OpenAPI 3.1 document from the typed route definitions, so the docs cannot drift from the implementation.

| Artifact | Where | Phase |
|---|---|---|
| Interactive docs (Swagger UI / ReDoc) | `https://<tenant-host>/api/docs` (disabled or auth-protected in production) | P2 |
| Committed schema | `backend/openapi.json` — regenerated by `make openapi`, diffed in CI to catch breaking changes | P2 |
| TypeScript client types | `frontend/packages/api-client` generated by `openapi-typescript` | P3 |
| Design conventions | [08 §5 API design](../08-backend-architecture.md#5-api-design) | P0 ✅ |
| Endpoint map (planned) | [08 §5 Endpoint map](../08-backend-architecture.md#endpoint-map-v1-shape-mvp-subset-marked-) | P0 ✅ |
| Integration API guide (API keys, webhooks) | this folder, `integration-guide.md` | V1 |

## Conventions (summary)
- Base path `/api/v1`; JSON; UTF-8; timestamps ISO-8601 UTC.
- Auth: session cookie (browser) or `Authorization: Bearer <api key>` (integrations, V1).
- Errors: `application/problem+json` (RFC 9457).
- Pagination: `?cursor=&limit=` (max 200), response `{ "items": [...], "next_cursor": "..." }`.
- Concurrency: `version` / `If-Match` → `409 Conflict`.
- Idempotency: `Idempotency-Key` header on commit/process/publish.
- Long-running work: `202 Accepted` + `GET /api/v1/jobs/{id}`.
- Tenant is always implied by the host; it is never a path or body parameter.
